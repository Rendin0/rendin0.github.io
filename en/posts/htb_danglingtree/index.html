    Enumeration#

    A port scan showed a standard Active Directory domain controller with a web server running on it.

    $ nmap 10.129.83.210
Nmap scan report for 10.129.83.210
Host is up (0.098s latency).
Not shown: 987 filtered tcp ports (no-response)
PORT     STATE SERVICE
80/tcp   open  http
88/tcp   open  kerberos-sec
135/tcp  open  msrpc

389/tcp  open  ldap
443/tcp  open  https
445/tcp  open  microsoft-ds

593/tcp  open  http-rpc-epmap
636/tcp  open  ldapssl
3268/tcp open  globalcatLDAP
3269/tcp open  globalcatLDAPssl
3389/tcp open  ms-wbt-server

    A quick look at ports 80 and 443 showed the default IIS placeholder page, nothing interesting. Most of the time a web server on a domain controller is there to work with certificates, so AD CS is probably set up on this machine. I kicked off a full port scan with nmap 10.129.83.210 -p- -T4. While nmap was running I quickly added an /etc/hosts entry and created a krb5.conf file to work with Kerberos later on.

    $ sudo nxc smb 10.129.83.210 --generate-hosts /etc/hosts
SMB         10.129.83.210   445    DC               [*] Windows 11 / Server 2025 Build 26100 x64 (name:DC) (domain:danglingtree.htb) (signing:True) (SMBv1:None) (Null Auth:True)

$ sudo nxc smb dc.danglingtree.htb --generate-krb5 /etc/krb5.conf
